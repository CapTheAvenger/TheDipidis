# Standard Rotation Checklist

What to do when the Pokemon TCG Standard format rotates — i.e. the oldest
legal set changes (e.g. SVI → TEF → PAF), or a brand-new English /
Japanese set releases.

After the 2026-05-27 Surface-Audit, the project has a **single source of
truth**: `data/format_window.json`. Editing that one file propagates the
rotation everywhere automatically — through CI, the deploy pipeline, the
inline JS snapshot in `index.html`, every scraper, and every UI label.

## The one-file edit

Open `data/format_window.json` and update:

```json
{
  "current_set": "CRI",         // newest released EN set (3-letter code)
  "oldest_legal_set": "TEF",    // lower bound of Standard rotation
  "set_release_date": "2026-05-22",
  "in_person_legal_date": "2026-06-05",
  "lag_days": 14,
  "current_set_jp": "M5",       // newest released JP set
  "jp_release_date": "2026-05-22"
}
```

That's it. Push to `main`. The deploy workflow does the rest.

## What auto-syncs from `format_window.json`

| Consumer | How it picks up the change | Trigger |
|---|---|---|
| `index.html` inline `window._formatWindow` | sed-rewritten by `bump-version.sh` and the `Cache-bust` step of `deploy-pages.yml` | Push to main |
| `window.getCurrentMetaFormat()` | Reads the inline snapshot synchronously | Page load |
| `KNOWN_META_FORMAT_CODES[0]` (app-core.js) | `appendLiveMeta` IIFE prepends `${oldest}-${current}` if not already present | First script run |
| Battle Journal `<option>` dropdowns | `populateMetaFormatSelects()` reads `window.KNOWN_META_FORMAT_CODES` on init and on edit-modal open | Tab visit |
| Meta Call past-meta filter | Reads `_formatWindow.current_set` via `endsWith` match | Every Meta Call render |
| Limitless Online scraper format tile | `_oldest_legal_set_fallback()` + `_current_set_fallback()` | Next scraper run |
| `labs_tournament_scraper._current_meta_key()` | Returns `${oldest_legal_set}-${current_set}` | Next labs run |
| `current_meta_analysis_scraper` `format_filter` | Self-heals against `_current_set_code()`; logs a warning if config drifts | Every run |
| CSS / JS / version.json cache-busters | `bump-version.sh` stamps a fresh `${TIMESTAMP}-${HASH}` | Push to main |

## What is NOT covered (and why)

- **Per-meta CSV chunk files** (`tournament_cards_data_cards_TEF-CRI.csv`,
  `labs_tournament_decks_TEF-CRI.csv`, etc.) are generated by scrapers
  once they see tournaments in the new format. They will appear
  automatically after the first weekly run that catches a post-rotation
  tournament. **No action needed; just wait for the next Tuesday 6 UTC
  cron.**

- **`tournament_cards_manifest.json` `meta_keys` array** is regenerated
  by `prepare_card_data.py` whenever a new chunk is added. Same
  mechanism — automatic on next weekly run.

- **Historical meta dropdown entries** in `index.html` (Battle Journal,
  Past Meta selectors) are now populated dynamically from
  `KNOWN_META_FORMAT_CODES`. The historical list inside
  `js/app-core.js` (`'TEF-POR', 'SVI-ASC', …`) is **append-only** —
  add new historical entries when a past meta closes, but the current
  meta auto-prepends.

## Sanity checks after a rotation

1. **Page load** — open the site, hard-refresh once. The Meta tile in
   the Limitless Online comparison HTML should display
   `${oldest_legal_set}-${current_set}` (e.g. `TEF-CRI`).
2. **Battle Journal** — open the Edit Tournament modal. The Meta Format
   dropdown should list `${oldest_legal_set}-${current_set}` at the top.
3. **Meta Call** — open the Past Meta dropdown. The current rotation
   should NOT appear there (it's the "live" meta, not a past one).
4. **CI logs** — after the next workflow run, search the
   `current_meta_analysis_scraper` log for
   `format_filter=… does not match format_window.current_set=…`. A
   warning here means `config/current_meta_analysis_settings.json` has
   drifted and self-heal kicked in; consider syncing the config too so
   the warning stops.

## If something looks stale

The most common cause is cache. The deploy pipeline stamps every push
with a unique `${TIMESTAMP}-${HASH}` baked into `APP_VERSION`,
`service-worker.js` `CACHE_NAME`, and `version.json`. On the next page
load, `index.html`'s version-check IIFE fetches `version.json` with
`cache: 'no-store'`, compares to the bundled `APP_VERSION`, and on
mismatch:

1. Sets a `sessionStorage` refresh marker (prevents infinite loops).
2. Purges every `caches` entry and `unregister`s every Service Worker.
3. Hard-reloads with `?_v=<new-version>` to bypass the HTTP cache.

If a user still sees stale data after this:

- Confirm the Pages deploy actually finished (Actions tab → Deploy to
  GitHub Pages → green check).
- Confirm `version.json` on the server matches the latest `APP_VERSION`
  (open the URL directly; bypass cache with cmd-shift-R).
- If the version-check itself is failing, check the browser console
  for fetch errors — those usually mean a CSP / CORS misconfiguration,
  not a cache problem.

## Files that contain rotation references (audit reference)

These files use `format_window.json` correctly and need no manual edit
on rotation. Listed for future audits so the same false-positives
don't reappear:

- `js/meta-binder.js` — falls through `window.getCurrentMetaFormat()`
- `js/custom-binder.js` — same
- `js/app-meta-cards.js` — same, plus oldest-prefix concat reads
  `window._formatWindow.oldest_legal_set`
- `js/app-core.js` — `mapSetCodeToMetaFormat` derives rotation cutoff
  from `_formatWindow.oldest_legal_set`
- `js/app-meta-call.js` — reads `_formatWindow.current_set`; literal
  `'TEF-POR'` strings appear only in `// e.g.` comments and are safe
- `backend/scrapers/limitless_online_scraper.py` — uses
  `_oldest_legal_set_fallback()` + `_current_set_fallback()`
- `backend/scrapers/labs_tournament_scraper.py` —
  `_current_meta_key()` returns the OLDEST-NEWEST rotation key
- `backend/scrapers/current_meta_analysis_scraper.py` — self-heals
  `format_filter` against the live `current_set`
